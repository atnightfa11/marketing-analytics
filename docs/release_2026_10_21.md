## Changes

- Report history follows the published site/day version, not today's subscription tier. Upgrades/downgrades no longer hide older Solo/Standard KPI windows or breakdowns. Forecast training reads that same history. Multiple plan copies are not summed.
- CSV preview/import rejects occupied live days and durable days that cannot safely be rebuilt after raw purge. Rollback requires the entire batch to remain retained; replacing part of an old batch disables that old batch's automatic rollback.
- Import-triggered reduction is scoped to that site. Purged days cannot be rebuilt from a later partial upload. Purge verifies actual KPI and breakdown row counts against the watermark.
- One unambiguous owner subscription supplies entitlements to its sites. Multiple subscriptions require support reconciliation.
- Standard owners can add sites from Manage websites. Sites two and three are included. Additional sites require explicit $5/month approval, starting at the next invoice without immediate proration. Durable pending operations and Stripe idempotency keys support retrying failed setup.
- New signups cannot collect before payment confirmation. Existing unbilled beta records remain complimentary. Canceled or expired-grace accounts stop collection but retain historical reporting. Payment retries do not restart grace.
- Password recovery uses existing SMTP. Links expire in 30 minutes, are single-use, and are stored only as hashes. Reset invalidates earlier dashboard sessions and other reset links. Token maintenance removes expired reset records. No CRM is required.
- Marketing signup uses the HttpOnly session cookie instead of storing bearer credentials. Both plans can resume checkout. The completion page checks backend subscription state, not a query-string session ID.
- API readiness checks schema state and publishes a code fingerprint; the worker checks schema before starting and logs the same fingerprint. Deployment smoke checks are authenticated and read-only.
- Subscription webhooks reconcile Stripe's current subscription under owner/plan row locks rather than applying potentially delayed event snapshots. Superseded subscriptions cannot rebind the account; one-off invoices do not change subscription state. Retrieval failures return a retryable error without committing the event receipt. A canceled subscription still revokes collection if its former price is no longer configured.
- PostgreSQL validation caught and fixed typed-date comparisons in import overlap/rollback queries. Published-day selection and daily insight grouping now explicitly use UTC, independent of the database session timezone.
- The October 22 CI preflight also corrected SDK lint globals, restored the mocked fetch after its test, and made the bundle-budget script compatible with Node 20.18. No SDK tracking behavior changed.

The runner ignores application `.env`/`DATABASE_URL`, creates synthetic data in a temporary cluster with no TCP listener, and shuts it down/removes it afterward. Subscription retrieval has a 10-second HTTP timeout and no inline network retries; failed deliveries remain eligible for Stripe webhook retry. No new migration is needed for this hardening beyond `2026_10_21_account_workflows` already listed above.
